# Failure lore (kept because it still bites)

- Trust the pane over `agent_status`: screen detection lags both ways; `done` = idle after unseen work; settled-without-token is an idle blip, not completion. `herdr agent explain <lane>` shows the reasoning.
- `agent read --source recent-unwrapped` can transiently return empty while an agent renders, and codex startup dialogs render only on the visible screen — herd's read fallback handles both; remember it when reading panes manually.
- Dialog doctrine: herd matches NO dialog text — five adversarial review rounds refuted every text-scrape classifier. Dialogs are prevented at the source instead: approvals via launch flags (`-a never`, `bypassPermissions`, `--approve`), folder trust via spawn's pretrust of the CLI config stores. Whatever still appears exits 3 with the pane excerpt, orchestrator answers by hand. Do not reintroduce screen-text classification.
- Tool self-updates mid-run are normal (herdr drops registrations; codex/pi re-raise trust dialogs). Restart the agent in the same pane (`herdr agent start` again), confirm the model banner, resend. Folder trust survives restarts; any re-raised dialog → send exits 3: answer it (`herdr agent send-keys <lane> enter`), resend.
- First-ever spawn into a fresh cwd can time out at agent startup ("timed out waiting for agent startup"). This is handled by `herd spawn` itself: it cleans up and retries once automatically. A spawn that still fails after the auto-retry is a real failure to diagnose. (Bitten live 2026-08-16; retry succeeded.)
- Codex sandbox blast radius, measured live (`-a never -s workspace-write`, macOS seatbelt): ALL network blocked including DNS (`CODEX_SANDBOX=seatbelt`, `CODEX_SANDBOX_NETWORK_DISABLED=1` — curl exit 6, even nslookup `bind: Operation not permitted`); writes only in lane cwd, `/tmp`, `$TMPDIR`; reads unrestricted. Escape hatch for lanes that legitimately need network: spawn with `-- -c sandbox_workspace_write.network_access=true` (verified live: HTTP 200 + DNS, filesystem still sandboxed). Full access would need `-s danger-full-access` — unverified, only with an explicit captain ruling.
- Codex worktree lanes cannot `git commit`: a linked worktree's git metadata lives under the main repo's `.git/worktrees/`, outside the seatbelt's writable roots. The lane reports the work uncommitted; the orchestrator commits in the lane's worktree — plumbing, not implementation. (Bitten live 2026-08-15.)
- Claude panes bury final output under ~45 lines of composer chrome — read with `--lines 60+`.
- Toast config (`[ui.toast]` in herdr config) is read at server start — editing it mid-session does nothing; `herd notify`'s osascript fallback covers it.
- Truncated pane report → have the worker write markdown to a temp file and reply with the path.
- Pi extensions can dirty a worktree AFTER the lane commits (e.g. a deferred pi-lens whole-file reformat). If the committed version is the verified one, discard the post-commit changes — do not re-open the lane for them. (Bitten live 2026-08-16.)
- Land-after-close is intentional: land may change `state` from `closed` to `done`; a later watch then exits agent-gone rather than closed because there is no separate closed boolean.
- A pi lane can die SILENTLY mid-turn — process exit, no error in pane or session file, watch exits 2 "agent gone" with zero detail. Diagnose by re-running the same task headless (`pi -p` in the lane's cwd) to capture stderr. Known cause class: an extension issuing LLM calls with its own system prompt through a claude-bridge model trips the bridge's prompt-capture guard, which currently throws fatally (bitten live 2026-08-17: pi-blackhole OM workers; fixed via blackhole `skipForProviders: ["claude-bridge"]` — keep that config on upgrades). The old "bridge lane answers with an instant empty turn" lore is retired: root-caused to mega-compact (erased) and guarded+auto-retried in claude-bridge `b458fcb`.
## Never restore a stale copy over a live shared `.herd/` (2026-09-03)
A lane copied `.herd/` aside before `git filter-repo`, then restored it with `cp -a aside/. .herd/` twenty minutes later. Every file another live lane had modified in between silently reverted (design docs, an owner tap log 30→14); files created after the copy survived, so it looked like a mysterious external restore. Rule: before restoring into any dir other lanes write to, check `herd status` for live lanes and either pause them or scope the restore; restore with `rsync -a --update` / `--ignore-existing`, or re-add only the paths the rewrite removed. `cp -a` is never the restore tool for a shared dir.
- Codex spawn "timed out waiting for agent startup" twice in a row (2026-09-05, codex-cli 0.153.2, gpt-6-astra): not a dialog — the TUI just takes >30 s to be ready. Workaround: `herdr tab create --no-focus --label <lane> --cwd <dir>` then `herdr agent start <lane> --kind codex --pane <id> --timeout 180000 -- <KIND_ARGS + overrides>`, then add the lane to `.herd/ledger.json` by hand (copy a sibling entry; `herd spawn` refuses to adopt a live agent whose cwd is an unmanaged worktree). `herd send`/`watch` work normally afterwards.
- Codex lanes cannot launch Chromium/Playwright browsers under the seatbelt sandbox (SIGABRT: Mach bootstrap denied; Safari computer-use denied too) — 2026-09-05. Fix that keeps the sandbox: ops starts a headless Chrome OUTSIDE the sandbox with `--headless=new --remote-debugging-port=9222 --remote-debugging-address=127.0.0.1 --remote-allow-origins='*' --user-data-dir=<scratch>` and hands the lane `http://127.0.0.1:9222`; the lane's Playwright uses `chromium.connectOverCDP(url)` (sandbox network access must be on: `-c sandbox_workspace_write.network_access=true`). Ops kills that Chrome at teardown.
- Frozen SQLite state dirs lose their `-wal`/`-shm` sidecars when ANY process opens the db in normal mode and closes as the last connection (SQLite checkpoints + deletes them; db bytes unchanged) — 2026-09-05 a frozen bench dir lost both at 06:29:44 during a review whose B2 analysis queried atoms. If a run hash-checks sidecars, that looks like tampering. Rule for every lane/reviewer touching a frozen dir: open with `file:...?mode=ro&immutable=1` (Python) or `sqlite3 -readonly` is NOT enough — immutable is. Restore = empty `-wal` + a 32 KiB `-shm` from any sibling frozen db (same sha fd4c9fda… for an empty WAL). Hash guards should not depend on sidecar presence.
